# Береговой прототип: первый день в Sail Academy

## Запуск

Из корня `sail-academy-sync`:

```powershell
cd client
npm.cmd install
npm.cmd run build
cd ../server
# При первом запуске: создайте .env по .env.example и задайте JWT_SECRET.
.venv/Scripts/python.exe start.py
```

Откройте http://127.0.0.1:8000, зарегистрируйтесь или войдите.
Сервер раздаёт `client/dist`, включая GLB. Для работы после сборки интернет не нужен.
Существующее окружение сервера — Python 3.12; зависимости описаны в `server/pyproject.toml`.
Если окружения ещё нет: `uv sync --project server` из корня проекта.

Режим разработки: запустите сервер, затем `npm.cmd run dev` из `client`.
Адрес в форме входа по умолчанию совпадает с адресом открытой страницы.
`VITE_BACKEND_TARGET` в `client/.env` задаёт адрес сервера для Vite-прокси.
Для LAN используйте `start.py --lan` и адрес сервера в локальной сети.

## Локация и маршрут (около 5–10 минут)

Управление: WASD/стрелки, Shift — бег, E — взаимодействие,
ПКМ + мышь — поворот камеры, колесо — масштаб.
Золотой маяк отмечает текущую цель; панель слева показывает расстояние и задание.

1. **Капитан Морозов**, у клуба `(4, 3)`: знакомство и маршрут инструктажа.
2. **Метеоролог Ли**, у флагштока `(-10, 4)`: прогноз, наблюдение за ветром, безопасность.
3. **Стойка жилетов**, у склада `(15, 5)`: нажать E. Жилет появляется на персонаже.
4. **Судья Анна**, под навесом `(10, 11)`: галсы, право пути, осторожность у причала.
5. **Конец пирса** `(-14, -26)`: нажать E, осмотреть учебную лодку.
6. **Капитан Морозов**: итог инструктажа и завершение первого дня.

**Михалыч** у начала пирса `(-10, -12)` — необязательный собеседник о морских словах.
В диалоге можно задать свой вопрос или выбрать готовый. Escape закрывает окно.
Этот этап заканчивается на берегу: посадка в лодку и плавание — следующий урок.
Невидимые границы удерживают игрока на суше и на пирсе.

## NPC и локальный ИИ

Клиент отправляет авторизованный `POST /api/ai/dialog` с `npc_id` и `text`.
Сервер сам определяет пользователя по JWT, проверяет близость к NPC и передаёт
личность, учебные факты, текущий инструктаж и последние реплики в локальный Ollama.
Подключение использует [официальный Ollama Chat API](https://github.com/ollama/ollama/blob/main/docs/api.md),
`POST /api/chat`, `stream: false`. В этом прототипе ответы приходят целиком, без стриминга.

По решению пользователя модель не скачивалась. При отсутствии модели, ошибке или
таймауте NPC отвечает по встроенному корпусу (`server/app/ai/content.py`).
Интерфейс явно показывает «Учебные ответы» или «Локальный ИИ · Ollama».
Готовые ответы — резервный сценарий, а не генеративный ИИ.
Когда модель будет установлена, достаточно указать её имя в `server/.env`:

```dotenv
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen2.5:3b
OLLAMA_TIMEOUT_SECONDS=35
```

Адрес и модель задаёт только сервер. Браузеры игроков не подключаются к Ollama напрямую.
Одновременно выполняется один диалог; при занятой очереди клиенту предлагается повторить запрос.
Отмена окна прерывает ожидание на клиенте; уже начатый инструктаж на сервере может завершиться
и сохраниться. При следующем входе панель загрузит сохранённое задание.
Промпт ограничивает модель учебными фактами, но это не полноценный проверенный RAG.

## Сохранения и API

- `GET /api/story` — текущее задание и полученный жилет.
- `POST /api/story/interact`, `{ "target": "vest" | "pier" }` — взаимодействие.
- `POST /api/ai/dialog`, `{ "npc_id": "captain" | "weather" | "judge" | "sailor", "text": "..." }` — диалог.

Все запросы требуют Bearer JWT. Сценарий принадлежит серверу: нельзя пропустить шаг
или получить предмет издалека. Локальный ИИ не управляет выдачей предметов и прогрессом.
В SQLite: `Progress` с `course_id=shore_intro`, `lesson_id=first_day`, `status` — этап;
`NPCMemory.memory_text` — ограниченная история последних реплик, отдельно для каждого игрока/NPC.
Прогресс и жилет восстанавливаются после входа; позиция персонажа пока начинается заново.
Жилет другого игрока пока не синхронизируется.

## Проверка

```powershell
cd client
npm.cmd run build
cd ../server
.venv/Scripts/python.exe -m pytest tests/test_shore.py -q
```

Тесты используют отдельную временную БД: прохождение, сохранение, порядок шагов,
дистанция, авторизация, независимая память игроков, fallback и контракт Ollama.
Настоящая генерация требует установленной модели и отдельно проверяется после её установки.
