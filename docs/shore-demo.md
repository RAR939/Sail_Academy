# Береговой прототип: первый день в Sail Academy

## Запуск

Из корня `sail-academy-sync`:

```powershell
cd client
npm.cmd install
npm.cmd run build
cd ../server
# При первом запуске: создайте .env по .env.example и задайте JWT_SECRET.
.venv/Scripts/python.exe start.py
```

Откройте http://127.0.0.1:8000, зарегистрируйтесь или войдите.
Сервер раздаёт `client/dist`, включая GLB. Для работы после сборки интернет не нужен.
Существующее окружение сервера — Python 3.12; зависимости описаны в `server/pyproject.toml`.
Если окружения ещё нет: `uv sync --project server` из корня проекта.

Режим разработки: запустите сервер, затем `npm.cmd run dev` из `client`.
Адрес в форме входа по умолчанию совпадает с адресом открытой страницы.
`VITE_BACKEND_TARGET` в `client/.env` задаёт адрес сервера для Vite-прокси.
Для LAN используйте `start.py --lan` и адрес сервера в локальной сети.

## Локация и маршрут (около 5–10 минут)

У конца пирса нажмите E, чтобы осмотреть учебный швертбот. В окне урока
можно выбрать корпус, мачту, парус, гик, руль и шверт: выбранная часть
подсвечивается, а гик с парусом, руль и шверт перемещаются. Это учебная
модель по мотивам ILCA, без заявленной точности заводских чертежей.
Судья Анна отвечает на вопрос «Как проходить гонку?».

Управление: WASD/стрелки, Shift — бег, E — взаимодействие,
ПКМ + мышь — поворот камеры, колесо — масштаб.
Золотой маяк отмечает текущую цель; панель слева показывает расстояние и задание.

1. **Капитан Морозов**, у клуба `(4, 3)`: знакомство и маршрут инструктажа.
2. **Метеоролог Ли**, у флагштока `(-10, 4)`: прогноз, наблюдение за ветром, безопасность.
3. **Стойка жилетов**, у склада `(15, 5)`: нажать E. Жилет появляется на персонаже.
4. **Судья Анна**, под навесом `(10, 11)`: галсы, право пути, осторожность у причала.
5. **Конец пирса** `(-14, -26)`: нажать E, осмотреть учебную лодку.
6. **Капитан Морозов**: итог инструктажа и завершение первого дня.

**Михалыч** у начала пирса `(-10, -12)` — необязательный собеседник о морских словах.
В диалоге можно задать свой вопрос или выбрать готовый. Escape закрывает окно.
Этот этап заканчивается на берегу: посадка в лодку и плавание — следующий урок.
Невидимые границы удерживают игрока на суше и на пирсе.

## NPC и локальный ИИ

Клиент отправляет авторизованный `POST /api/ai/dialog` с `npc_id` и `text`.
Сервер сам определяет пользователя по JWT, проверяет близость к NPC и передаёт
личность, учебные факты, текущий инструктаж и последние реплики в локальный Ollama.
Подключение использует [официальный Ollama Chat API](https://github.com/ollama/ollama/blob/main/docs/api.md),
`POST /api/chat`, `stream: false`. В этом прототипе ответы приходят целиком, без стриминга.

По решению пользователя модель не скачивалась. При отсутствии модели, ошибке или
таймауте NPC отвечает по встроенному корпусу (`server/app/ai/content.py`).
Интерфейс явно показывает «Учебные ответы» или «Локальный ИИ · Ollama».
Готовые ответы — резервный сценарий, а не генеративный ИИ.
Когда модель будет установлена, достаточно указать её имя в `server/.env`:

```dotenv
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen2.5:3b
OLLAMA_TIMEOUT_SECONDS=35
```

Адрес и модель задаёт только сервер. Браузеры игроков не подключаются к Ollama напрямую.
Для Ollama на другом компьютере укажите доступный из сети адрес этого компьютера
в `OLLAMA_URL`. Сервер Ollama должен принимать подключения из локальной сети.
Одновременно выполняется один диалог; при занятой очереди клиенту предлагается повторить запрос.
Отмена окна прерывает ожидание на клиенте; уже начатый инструктаж на сервере может завершиться
и сохраниться. При следующем входе панель загрузит сохранённое задание.
Промпт ограничивает модель учебными фактами, но это не полноценный проверенный RAG.

## Сохранения и API

- `GET /api/story` — текущее задание и полученный жилет.
- `POST /api/story/interact`, `{ "target": "vest" | "pier" }` — взаимодействие.
- `POST /api/ai/dialog`, `{ "npc_id": "captain" | "weather" | "judge" | "sailor", "text": "..." }` — диалог.

Все запросы требуют Bearer JWT. Сценарий принадлежит серверу: нельзя пропустить шаг
или получить предмет издалека. Локальный ИИ не управляет выдачей предметов и прогрессом.
В SQLite: `Progress` с `course_id=shore_intro`, `lesson_id=first_day`, `status` — этап;
`NPCMemory.memory_text` — ограниченная история последних реплик, отдельно для каждого игрока/NPC.
Прогресс и жилет восстанавливаются после входа; позиция персонажа пока начинается заново.
Жилет другого игрока пока не синхронизируется.

## Проверка

```powershell
cd client
npm.cmd run build
cd ../server
.venv/Scripts/python.exe -m pytest tests/test_shore.py -q
```

Тесты используют отдельную временную БД: прохождение, сохранение, порядок шагов,
дистанция, авторизация, независимая память игроков, fallback и контракт Ollama.
Настоящая генерация требует установленной модели и отдельно проверяется после её установки.

## HTTPS в локальной сети

На серверном компьютере в папке `server` запустите:

```powershell
.venv/Scripts/python.exe start.py --lan --https
```

С `uv`: `uv run python start.py --lan --https`. Если выбран IP не той сети,
укажите IPv4 вручную: `uv run python start.py --lan --https --ip 192.168.1.10`.
Игроки открывают именно напечатанный адрес с `https://`. Для шифрования всего
пути от браузера открывайте собранный клиент через сервер: обычный Vite на
`http://...:5173` сам по себе не шифрует соединение с браузером.

При первом запуске нужен OpenSSL (подойдёт рабочий вариант из Git for Windows).
Скрипт создаст сертификат `lan-cert.pem` и закрытый ключ `lan-key.pem`,
выведет адрес `https://IP:8000`. Клиенты используют тот же адрес; WebSocket
автоматически перейдёт на WSS. Для проверки доверия нужно установить **только
сертификат** `lan-cert.pem` как доверенный на каждом клиентском устройстве и
перезапустить браузер. Закрытый ключ `lan-key.pem` остаётся на сервере.
Установка доверия зависит от ОС и браузера; сертификат сам по себе не становится
доверенным. Если IP сервера изменился или старые файлы сертификата неполные,
скрипт создаст отдельную подпапку в `server/certs`, не перезаписывая старые
ключи. Путь к актуальному сертификату выводится при запуске; новый сертификат
нужно заново установить на клиентах. Предупреждение браузера до установки
доверия к самоподписанному сертификату ожидаемо.

Текущий мир ещё не реализует требование кэширования в 10%: береговая геометрия
создаётся одной сценой, модели окружения предзагружаются. Для ограничения
потребуется разбить их на чанки, учитывать размеры всей геометрии и текстур и
выгружать дальние чанки. Счётчик не должен учитывать только JSON-манифест.

## Тренировочная гонка

В хабе подойдите к лодке в конце пирса, нажмите E и выберите «Выйти на тренировочную трассу». Сервер создаёт отдельную комнату и размещает лодку за линией старта.

- A/D или стрелки влево/вправо — румпель; Q/E — подобрать/потравить шкот. Парус и гик отклоняются на соответствующий угол, переходят на другой борт при смене галса.
- Мышь и колесо — камера. Скорость, ветер, угол к ветру и угол шкота видны слева.
- Стрелка в панели и стрелка над водой с наветренной стороны лодки показывают, куда дует истинный ветер.
- Стартуйте между флагом S и судейской лодкой в сторону знака 1. Огибайте четыре пронумерованных знака 1 → 2 → 3 → 4, оставляя каждый слева. Следующий знак подсвечен; жёлтый луч от него показывает контрольную линию огибания. Пересеките луч с правильной стороны в пределах 18 м от буя. После знака 4 финишируйте между судейской лодкой и флагом F в сторону знака 1. Пересечение стартовой половины на финише не засчитывается.
- Время начинает идти после старта и останавливается на финише. Кнопка «Вернуться на берег» закрывает тренировку. Для нового заезда снова подойдите к лодке.

Движение, ветер и отметки рассчитываются сервером. Поляра учебная: тяга плавно снижается при курсе ближе 40°, нулевая тяга задаётся до 25° истинного ветра. Это не измеренная поляра ILCA и параметры нужно настраивать по ощущениям и данным. Огибание проверяется пересечением конечного луча с правильного направления, это приближённая учебная проверка, а не полный судейский движок. Тактические правила, штрафы и сохранение истории пока не реализованы. Каждое нажатие создаёт отдельную комнату, интерфейса присоединения к чужой гонке или общего старта пока нет.
